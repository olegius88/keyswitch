# Prefix v1: обученное переключение на полуслове

Отдельный локальный классификатор для незавершённых EN/RU-префиксов.
Рабочий артефакт — `prefix-v1-2f0c54bf546b`, 198 942 байта, 2 598 разреженных
признаков. Он не использует веса или extractor завершённых слов context-v1.
Решения — оставить, преобразовать или ждать; общий четырёхклассовый контейнер
содержит также `suggest`, но такой метки в этом обучении нет.

В `assist` при включённых контексте и ранней смене модель оценивает каждый
новый префикс в проверенной области 4–12 символов. При score `convert` ниже
0.999 ждёт продолжения. Это порог, выбранный по calibration, а не обещание
99.9% правильного понимания намерений реального пользователя. Настройка
минимума может задержать проверку; меньший минимум не расширяет область модели.
В `off`/`shadow` и без учёта контекста сохраняется прежний префиксный алгоритм.

## Данные и разделение

Использован уже замороженный публичный
[CC0-снимок Tatoeba](../context_v2/sources/README.md) с его исходной контрольной
суммой. Частные логи и переписка не используются. Из слов строятся авторские
ситуации: верная/неверная раскладка, пустой контекст, комментарии, команды,
идентификаторы, английские вставки и опечатки с удалённой буквой. Каждый
последующий символ образует отдельное наблюдение.

Разделение выполняется **до разворачивания последовательностей** по первым
трём физическим клавишам: варианты языка, контекста и словарного профиля
одного семейства не расходятся по разделам. Общие короткие префиксы из одного
или двух символов имеют метку ожидания и не могут запустить раннюю модель.
Слова ограничены 5–16 символами, до 2 500 на язык и четырёх на семейство.
Это не исчерпывающий словарь и не независимые человеческие намерения.

| Раздел | Наблюдения префиксов, включая оба профиля | Семейства |
| --- | ---: | ---: |
| Train | 432 098 | 1 352 |
| Development | 60 048 | 193 |
| Calibration | 76 084 | 232 |
| Test | 58 000 | 185 |

Новый split относится к новой задаче префиксов. Старые эксперименты могли
видеть слова из этого публичного снимка: это **не** глобально неизвестный
источник и не новые реальные диалоги. Шаблоны окружения повторяются между
частями; соседние слова не объявляются независимыми. Метка ожидания для
ошибочной раскладки с возможным исходным продолжением опирается на portable
словарь, но не на порог или решение прежнего early-switch алгоритма.

Признаки: возможность/частота продолжений в обоих языках, известность,
n-граммы, длина и форма префикса, язык последних 512 символов, последние слова,
признаки комментария/присваивания/кавычек, приложение и роль поля. Признаки
словарей frozen отдельно для portable и эталонного Hunspell. Оба профиля —
два измерения одних ситуаций, а не независимые наборы пользовательских вводов.

## Обучение и зафиксированный результат

Детерминированный AdaGrad, до 35 эпох; эпоха выбрана по development loss,
порог — только по calibration (0 ложных вмешательств). Train определяет
словарь признаков и веса классов. До test сохранены config, кандидат и seal.
Предыдущий pre-test seal с теми же весами сохранён в `development-history`:
изменялась проверка допустимости отчётов, не выбор параметров по test.

[Отчёт test](report.json): 3 911 ситуаций, 1 848 с неверной раскладкой,
каждая проверена в двух словарных профилях. Считается первое вмешательство
за последовательность, а не число уверенных прогнозов на отдельных буквах.

| Метрика | Portable | Reference Hunspell |
| --- | ---: | ---: |
| Нужная замена до конца слова | 1 750 / 1 848 (94.70%) | 1 767 / 1 848 (95.62%) |
| Нужная замена до границы включительно | 1 786 / 1 848 | 1 801 / 1 848 |
| Ложное вмешательство | 2 / 3 911 | 2 / 3 911 |
| Ложное вмешательство в командах/идентификаторах | 0 | 0 |
| Ложное вмешательство изолированного legacy-prefix | 274 | 318 |

Ошибки новой модели: опечатки `recnt` и `recntly`. Это одни и те же две
ситуации в двух профилях. Они сохранены в отчёте; исключения для этих слов
не добавлялись, порог по раскрытому тесту не менялся. Сравнение legacy-prefix
не равно сравнению с полным прежним `assist`: там ранняя замена была выключена.

Заранее заданные условия пройдены в каждом профиле: минимум 1 000 ситуаций,
ложные вмешательства ≤0.1% всех ситуаций, ноль технических ложных замен,
раннее исправление ≥70% нужных случаев, ложных вмешательств не больше legacy.
Это не сертификат отсутствия ошибок или проверка всех приложений.

## Движок и ограничения

[Сквозной отчёт](engine-report.json): 288 заранее выбранных test-ситуаций,
по 32 на категорию; два словаря × наблюдаемый/симулированный контекст поля.
Физические клавиши фиксированы, отображаемые символы следуют новой раскладке;
проверяется конечный текст вместе с двумя пробелами.

В каждом режиме восстановлены 128/128 ошибочных вводов против 121/128 у
прежнего `assist` без ранней модели. До окончания слова — 128/128 с наблюдаемым
контекстом и 121/128 с симулированным чтением поля. Потерь/добавлений символов
по длине нет. В 10 из 160 изначально корректных отрицательных примеров
остаются **прежние** ложные замены на границе слова; новый ранний путь их
не увеличил, но модель завершённых слов ими не исправлена. Это видимый
редактор внутри процесса, не реальный Windows hook или произвольный чат.

Движок ждёт отпускания всех клавиш, повторяет прогноз на актуальном префиксе,
сохраняет идентификатор поля при rollover и проверяет его перед инъекцией.
Фокус, безопасный диапазон замены, явная ручная раскладка, исключения и запреты
после Undo выше модели. ALL-CAPS/camelCase и неподдержанный диапазон не
обрабатываются ранней моделью. Недоступные/повреждённые веса запрещают именно
модельную раннюю замену, не ручной Pause и не проверку завершённого слова.

Модель не видит будущие символы, не является парсером языка программирования
или универсальным распознавателем паролей. Код без предшествующего синтаксиса,
редкие имена, иной словарь, нетипичный редактор и изменённый контекст могут
вести себя иначе. Ошибки допустимо оставлять без вмешательства. Ручной выбор
не заменяется вероятностным решением. Чтение настоящего поля остаётся opt-in;
соседний текст не добавляется в диагностику `prefix_decision`.

Локальная проверка 07.09.2026: 650 тестов, 100% configured line/branch coverage,
strict mypy для Linux и Windows-области CI. Нативный X11 E2E подтвердил
`hello ghbd` → `hello прив` до следующего символа, затем точный результат
`hello привет ` и одну запись истории. Первый вариант новой проверки ошибочно
ждал завершённую запись истории ещё на полуслове; проверка исправлена согласно
контракту движка и полный E2E повторно пройден. Нативный Windows E2E и сборка
установщика в этой локальной доработке не запускались.

Замер на этом Linux-хосте: извлечение признаков и прогноз для первых 1 024
development-префиксов portable длиной 4–12, один проход: медиана 0.0798 мс,
p95 0.2194 мс, максимум 0.9959 мс. Без чтения поля, клавиатурной очереди и
инъекции; это не гарантия такой же задержки в приложениях или на другом ПК.

## Проверка без изменения кандидата

```sh
PYTHONPATH=src python3 tools/prefix_corpus.py
PYTHONPATH=src python3 tools/train_prefix_model.py verify
PYTHONPATH=src python3 tools/evaluate_prefix_engine.py --verify
PYTHONPATH=src python3 tools/verify_prefix_model.py
```

Запускать тяжёлые проверки последовательно. Обучение работает с замороженными
числовыми признаками и C-оптимизатором; engine replay требует reference
словарей. `verify` побайтно повторяет веса, seal и отчёт без продвижения.
Пакеты проверяют hash активного артефакта, corpus/seal/test и точный engine
отчёт. После раскрытия test команда `fit` запрещена; новый эксперимент требует
отдельной контрольной выборки. Engine-only `--refresh-runtime` архивирует
предыдущий отчёт и не выдаёт повторный тест за независимую оценку.
