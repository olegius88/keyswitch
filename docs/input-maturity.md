# Зрелость ввода EN/RU: сценарии, гарантии и ограничения

Аудит 2026-09-05 по обращениям пользователя и исходникам 0.13.0. Этот документ
сохраняет матрицу требований доработки 0.14.0; уточнения ниже учитывают 0.15.0–0.16.0.
Исторические результаты 0.14.0 не являются счётчиком тестов текущего дерева.
[Актуальные команды проверки](verification.md),
[контекстный помощник](context-assistant.md), [диагностика по журналу](troubleshooting.md).

## Матрица текста

Переключение раскладки сохраняет физически набранные символы и регистр. Оно не
исправляет орфографию: `срабатыает` не должно самовольно становиться `срабатывает`.

| Класс | Примеры | Ожидаемое поведение |
| --- | --- | --- |
| Основные пары | `ghbdtn → привет`, `руддщ → hello` | Замена только накопленного токена |
| Русская `ё`, регистр | `ёлка`, `Ёлка`, `всё`, `все` | Не приравнивать `ё` и `е` в выводимом тексте; сохранять регистр |
| Shift и Caps Lock | `Привет`, `ПРИВЕТ`, Caps Lock меняется внутри слова | Для каждой буквы учитывать состояние в момент нажатия; дождаться отпускания клавиш |
| Русские короткие слова | `а`, `и`, `у`, `в`, `к`, `с`, `о`, `я`, `не`, `ли`, `бы` | Одинокая `e` может быть переменной или русским `у`; без контекста не обещать автоматический выбор |
| Английские короткие слова | `a`, `I`, `to`, `in`, `as`, `if`, `or` | Не превращать автоматически любую двухбуквенную последовательность в частое слово |
| Коллизии словарей | `дев/ltd`, `мы/vs`, `ли/kb`, `то/nj` | Учитывать контекст, ручной выбор языка и запреты пользователя |
| Дефис | `кто-то`, `по-русски`, `Санкт-Петербург`, `mother-in-law` | Не запускать замену половины слова на внутреннем дефисе |
| Разные дефисы | `-`, `‐`, `‑` | Сохранять исходный знак, не подменять типографику |
| Апостроф | `don't`, `we’re`, `O’Neill` | Не разрывать токен на внутреннем апострофе |
| Пунктуация/буквы EN/RU | `,fpf`, `j,ob[`, `ghbdtn,` | Отличать запятую от физической клавиши `б`; сохранять пунктуацию границы |
| Конец фразы | `. , ! ? ; : … — » ) ] }` | Не удалять и не удваивать разделители |
| Кавычки и вложения | `«текст»`, `“text”`, `"text"`, `(текст)` | Не дописывать парные знаки; автозакрытие редактора требует отдельного теста приложения |
| Пробелы | один/два/три, NBSP, narrow NBSP, thin space | Сохранять точное число и кодовые точки; после дополнительного пробела старое слово недоступно для Pause/Undo |
| Перевод строки/переход | Enter, Numpad Enter, Tab, Shift+Tab | Не удалять текст после уже доставленного действия и не повторять действие |
| Цифры | `pm2`, `зь2`, `2ghbdtn`, версии, номера | Полный токен доступен Pause; автоматическая защита цифр |
| Код | `snake_case`, `camelCase`, `APIKey`, `foo=bar`, `--flag` | Не исправлять по отдельности части идентификатора |
| Адреса и пути | `user@host`, `@handle`, `/path`, `C:\path`, URL | Сохранять структурные маркеры в токене; защищать распознанный структурный токен |
| Смешение языков | `запусти pm2`, `открой README`, имена, бренды | Не считать весь абзац одним языком; сомнительный токен оставить пользователю |
| Другие языки | украинский, казахский, немецкий, французский, диакритика | EN/RU модель не является классификатором всех языков; не выдавать это за полную поддержку |
| Составной Unicode | emoji, combining marks, ZWJ, IME, dead keys | При отсутствии связи «одна клавиша — одно удаление» прекращать накопление до следующей границы |
| Очень длинный ввод | более 256 физических нажатий | Ограничить буфер; не исправлять оторванный от начала суффикс |

Матрица является одновременно списком требований и тестовым планом. Все строки
не следует считать проверенными во всех приложениях: конкретные автоматические
проверки перечислены ниже, платформенные ограничения — в конце.

## Правила безопасной замены

- Клавиши, из которых состоит заменяемое слово, должны быть отпущены. Это
  относится и к раннему переключению, и к буквам, пришедшим со старой раскладкой.
- Backspace, стрелки, выделение/горячие клавиши, клики и колесо мыши делают
  сохранённую позицию недействительной. Смена окна или нативного поля сбрасывает
  отложенную замену и языковой контекст предыдущего поля.
- Очередь с Enter, Tab, навигацией, модификаторами или командой смены языка
  отменяет отложенную замену. Отмена оставляет эти события для обычной обработки.
- Windows перехватывает Enter/Numpad Enter/Tab до доставки. На отпускании
  исправляется только слово, затем действие передаётся ровно один раз. Ввод
  следующего сообщения удерживается и воспроизводится после действия; второй
  Enter создаёт следующую такую же операцию. Уже доставленные Enter/Tab никогда
  не удаляются и не повторяются. В X11 перехват недоступен, поэтому его элементы
  настроек отключены; работают пробел, пауза, пунктуация и ручной Pause.
- Shift/Ctrl/Alt/Super с Enter/Tab остаются сочетаниями приложения. Enter
  подтверждения обучения не отправляется в чат. При сбое замены, смене фокуса,
  перемещении указателя или отсутствии отпускания за две секунды отложенное
  действие отменяется с сообщением. Автоматически повторять его нельзя.
- Undo действует только у неизменённого последнего исправления в пределах
  времени отмены. Возвращение курсора назад не восстанавливает право на Undo.
- После замены по Pause или по таймеру без разделителя исправленное слово
  остаётся текущим токеном. Дописывание, Backspace и повторный Pause работают
  со всем словом, а не с оторванным суффиксом.
- Win32 удерживает физический ввод во время коррекции, маркирует воспроизведение
  отдельным `dwExtraInfo` и освобождает удержание даже при исключении. Повторный
  вызов hook для такого воспроизведения не кладёт его обратно в буфер.
- Частичный `SendInput` — неопределённый результат текста. Нельзя повторять весь
  частично выполненный пакет и считать, что это безопасный откат.

## Что означает журнал

`correction_id` связывает результат попытки; `correction_aborted` объясняет отказ
до инъекции. `correction_failed` содержит причину сбоя. `correction_applied`
означает завершение отправки событий backend, а не чтение конечного текста.
`text_verified=false` явно отражает отсутствие такого чтения.
`action_deferred` отмечает перехват Enter/Tab; `action_delivered` — отправку
действия после проверки/замены; `action_cancelled` и `action_failed` объясняют
отмену либо сбой. Это отправка события, а не подтверждение сервером чата.

Совместимое поле `keys_during_injection` считает события нажатия **и** отпускания.
`keypresses_during_injection` выделяет нажатия, но также не равно числу символов
(например, Shift символа не добавляет). Ни одно из этих полей само по себе не
доказывает потерю текста. `deleted_characters` включает учтённый поздний ввод;
`late_keys` и `held_keys` описывают соответствующие группы событий.

Технический режим пишет слова и решения, в том числе слова без исправления.
Это чувствительный диагностический файл. Слова приложений-исключений маскируются
перед записью в диагностику; обычная история и технический журнал —
разные механизмы.

## Проверки и оставшиеся границы

- `tests/test_input_integrity.py`: видимый текстовый буфер с курсором и отправкой,
  таблицы пунктуации/пробелов/токенов, очередь, Unicode, фокус, Undo, ручные
  исправления, короткое обучение; Win32 повторный вызов hook и автоповтор Enter.
- `tests/test_engine_behaviour.py`, `test_core.py`: существующие сценарии Pause,
  раннего переключения, ручного языка, обучения и диагностических событий.
- `tests/test_windows_backend.py`, `test_x11_backend.py`: порядок событий, отказ
  системного вызова, раскладки и модификаторы.
- `tests/test_action_boundary.py`: видимый редактор поверх Win32 backend с
  повторным вызовом hook из SendInput; исправление до отправки, два быстрых
  сообщения, автоповтор и перекрытие клавиш, отказ инъекции, фокус, таймаут.
- `tests/e2e_x11.py`: настоящее GTK-поле и XRecord/XTEST. Windows native E2E
  запускается отдельно на Windows; Linux-моки его не заменяют.

Историческая локальная проверка доработки 0.14.0, 2026-09-05:

- `dbus-run-session -- xvfb-run -a ./tests/run_coverage.sh`: 548 тестов, все
  успешны; 6369 исполняемых строк и 1716 ветвей покрыты на 100% в существующем
  контуре `.coveragerc`. Нативные Windows-обвязки и Windows UI исключены из
  этого контура, поэтому 100% не означает проверку всех платформенных файлов.
- `./tools/typecheck.sh` с установленным окружением mypy: 72 файла без ошибок.
- `tests/e2e_x11.py` под Xvfb с раскладками `us,ru`: `E2E_OK`,
  `MENU_LAYOUT_SELECTION_E2E_OK`, `EARLY_SWITCH_E2E_OK`.
- Нативный `tests/e2e_windows.py` расширен проверками: подтверждающий Enter
  не отправляет текст; `ghbdtn` + Enter передаёт в обработчик отправки `привет`
  один раз. На этой Linux-машине нативный Windows-тест не выполнялся.

Остаются случаи без универсальной гарантии: асинхронное автодополнение редактора,
изменение DOM/текста самим приложением, парольные/защищённые поля без явного
исключения, другой уровень привилегий, игры, RDP/виртуальные машины, Wayland,
экранные клавиатуры и сложные IME. XRecord не удерживает реальный ввод; остаётся
гонка между наблюдением события и XTEST. С 0.15.0 реализовано опциональное
чтение через UI Automation/AT-SPI и повторная проверка снимка **до** замены.
Оно выключено по умолчанию и не работает с любым полем; универсальной проверки
текста **после** замены по-прежнему нет. Обещание «все нюансы учтены» было бы неверным.

В доработке 0.14.0 базовый detector, KSLM, пороги и frozen provenance-входы
не менялись. В 0.15.0 добавлена отдельная контекстная политика; в 0.16.0 её
расширенный кандидат отклонён, рабочие веса сохранены.
Новые языковые эвристики должны идти через отдельный
корпус ложных срабатываний и [runbook модели](intent-model-runbook.md), а не через
обход её проверки качества.
