# Карта документации KeySwitch

Документация этого тега описывает KeySwitch 0.18.0. В ветке `main` могут быть
последующие изменения `Unreleased`. Версию установленного приложения проверяйте
через `keyswitch --version`; версия приложения, KSLM и контекстного классификатора
имеют независимую нумерацию.

## Пользователю

- [LogCourier](../apps/logcourier/README.md): отдельный сборщик файлов логов в
  Telegram для Windows/Linux; интерфейс настройки бота, группы и источников.

- [README на русском](../README.md) / [English](../README.en.md): установка,
  настройки, горячие клавиши, данные, обновления и ограничения платформ.
- [Диагностика проблем ввода](troubleshooting.md): пустой журнал, Pause,
  Enter, лишние/пропавшие символы и сведения для воспроизведения.
- [Контекстный помощник](context-assistant.md): `assist`/`shadow`/`off`,
  доступ к полю, приватность, обучение и границы качества.
- [Матрица зрелости ввода](input-maturity.md): требования из обращений,
  пунктуация, пробелы, регистр, короткие слова и платформенные тесты.
- [Справка `man keyswitch`](../packaging/keyswitch.1): Linux CLI и пути данных.

Метрики одной строки таблицы не доказывают качество остальных. Доставка клавиш
и целостность текста проверяются отдельно от классификации. Исторические
результаты в карточках, отчётах и changelog сохраняют исходные числа и область
применимости; они не являются текущей статистикой реальных чатов.

## Как поддерживать инструкции актуальными

При изменении поведения сверяйте обе версии README, man-страницу и описания
настроек в [GTK UI](../src/keyswitch/ui.py) и
[Windows-каталоге](../src/keyswitch/windows_ui_model.py). При изменении моделей
обновляйте их собственные инструкции и доказательства, не переписывая
израсходованные seal/test-результаты. При изменении CI сверяйте
[профили конвейера](../tools/release_pipeline.py),
[Tests workflow](../.github/workflows/tests.yml),
[Release workflow](../.github/workflows/release.yml) и инструкцию проверки.
Текстовое упоминание шага не добавляет этот шаг в конвейер.
