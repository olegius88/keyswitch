# LogCourier

Личный сборщик логов для Windows и Linux: работает в трее, читает выбранные файлы,
сохраняет новые фрагменты в локальную очередь и отправляет ZIP-архивы в закрытую
группу Telegram. Отдельная программа в `apps/logcourier` репозитория KeySwitch;
имеет свои зависимости и не меняет обработку клавиатуры KeySwitch.

**Версия 0.1.1 — Windows-инсталлятор и улучшенная доставка.** Проверена локально на Linux. Реальный
бот проверен через `getMe`, токен сохранён в системном хранилище. На синтетическом
файле проверены отправка в группу, закрепление каталога и скачивание с побайтовым
сравнением. Нативная сборка Windows должна пройти отдельную проверку.
Автоотправка и разрешение на передачу содержимого по умолчанию выключены.

## Быстрый запуск

### Установка в Windows

Для Windows добавлена сборка одного установщика `LogCourier-Setup-0.1.1-x64.exe`.
Он устанавливает программу для текущего пользователя в
`%LOCALAPPDATA%\Programs\LogCourier`, создаёт ярлык в меню «Пуск» и, по желанию,
на рабочем столе. Python и ручная распаковка `_internal` не нужны.
Установщик публикуется после нативной Windows-проверки в CI в отдельном
[релизе LogCourier](https://github.com/olegius88/keyswitch/releases/tag/logcourier-v0.1.1).

Перед установкой поверх переносимой версии или обновлением выберите **Выход**
в меню трея старого сборщика: крестик только скрывает окно. Настройки и очередь
лежат отдельно от программы, поэтому существующий профиль будет использован
при запуске установленной копии. Не запускайте две копии одновременно.
Если автозапуск был включён у переносимой версии, после установки выключите
и снова включите его во вкладке **Отправка**, чтобы обновить путь.

Установщик не включает автозапуск и отправку логов. Эти настройки выбираются
в программе. Удаление через список приложений Windows убирает установленную
программу и её запись автозапуска, но **сохраняет настройки, очередь и токен
в системном хранилище**. Запись автозапуска другой переносимой копии не удаляется.

### Запуск из исходников и переносимая версия

Из исходников нужны Python 3.12+ и интернет для установки зависимостей:

```bash
./run.sh
```

В Windows из PowerShell в папке проекта:

```powershell
.\run.ps1
```

Если политика PowerShell запрещает запуск скрипта, не отключайте её глобально:
используйте обычные команды установки вручную:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m logcourier
```

Собранная переносимая версия не требует отдельного Python. Запускайте файл
`LogCourier` (Linux) или `LogCourier.exe` (Windows) **вместе с соседней папкой
`_internal`** — не переносите один исполняемый файл отдельно.
На Linux нужны графическая сессия и системные библиотеки Qt/X11. Для значка в
трее среда рабочего стола должна поддерживать системный трей; если его нет,
окно остаётся открытым. При доступном трее крестик скрывает окно, не останавливая сбор.
Полный выход — пункт «Выход»
в меню трея. Если трей временно недоступен, окно остаётся открытым.
В Windows `LogCourier.exe` — оконная программа без консоли; для команд и диагностики
предназначен соседний `LogCourier-cli.exe`. Ошибка запуска оконной версии показывается
сообщением и сохраняется в `startup-error.txt` в каталоге данных LogCourier.
Для запуска из исходников на Ubuntu может потребоваться пакет `libxcb-cursor0`.
На текущем компьютере он распакован только в `.local/qt-deps`, без установки в ОС;
`run.sh` учитывает этот локальный путь. Собранный здесь Linux-архив предназначен
для текущей Ubuntu 26.04; совместимость со старыми дистрибутивами не проверена.

## Подключение Telegram

1. Создайте отдельного бота через `@BotFather`. Не присылайте токен в переписку,
   не коммитьте его и не помещайте в установщик.
2. Создайте **закрытую группу без публичного @имени**, добавьте бота
   администратором с правом закреплять сообщения. Не давайте лишних прав.
3. Откройте вкладку **Telegram**, вставьте токен в скрытое поле.
4. Отправьте в группе `/start@имя_вашего_бота`, нажмите **Найти группы**.
   Если группа не найдена, введите её отрицательный Chat ID вручную.
   Поиск использует недавние обновления Bot API, а не историю переписки.
   При настроенном webhook поиск не меняет его и предлагает ручной ввод ID.
5. Нажмите **Проверить подключение**. Эта операция ничего не отправляет.
   При переносе с другого компьютера остановите там сборщик и нажмите
   **Подключить существующий каталог**, затем подтвердите перенос. Это сохраняет
   доступ к уже отправленным архивам; не запускайте два отправителя одновременно.
6. На вкладке **Файлы** добавьте нужный лог. Например, для KeySwitch выберите
   `keyswitch.log`; `keyswitch.log.1` … `.5` будут учтены как ротации.
   Не добавляйте ротации ещё и отдельными источниками — это продублирует сбор.
7. Если нужны накопленные логи, включите **Включить уже существующие записи**
   при добавлении файла. Без флажка исходная позиция устанавливается в конец
   файлов при **первом запуске сбора**, а не при выборе файла.
8. На вкладке **Отправка** разрешите передачу содержимого и нажмите
   **Отправить сейчас**. Убедитесь, что архив и каталог появились в группе.
9. При необходимости включите автоотправку, выберите интервал и сохраните.

Токен хранится в Windows Credential Locker либо Linux Secret Service, а не в
`config.json`. Если системное хранилище недоступно, снимите флажок сохранения:
тогда токен действует только до выхода. Ранее сохранённый токен этот флажок
**не удаляет**; удаление выполняется через системный менеджер секретов.

Смена группы или редактирование токена снимают разрешение в интерфейсе —
нужно подтвердить нового получателя. Старые архивы в очереди остаются привязаны
к прежним ID бота и группы и не перенаправляются автоматически.

## Поведение и ограничения

- Читаются только выбранные обычные файлы и числовые ротации `.1` … `.N`.
  Символьные ссылки, устройства, каналы и `.gz` не читаются.
- Исходные файлы не изменяются. Передаются исходные байты, в том числе русский
  текст, CRLF, пробелы и незавершённые строки. Фрагмент может разрезать очень
  длинную строку или многобайтовый символ; восстанавливайте байты до декодирования.
- Сбор — примерно каждые 5 секунд между циклами доставки, до 16 фрагментов за
  проход. Фрагмент до 2 МиБ до сжатия хранится локально; это не отдельное сообщение.
  Перед отправкой новые фрагменты разных источников объединяются в ZIP-пакеты
  до **19 000 000 байт**. При наступлении интервала отправляется накопленное,
  даже если пакет ещё не заполнен. Искусственного дополнения до лимита нет.
  Пакет содержит `manifest.json` и исходные ZIP во вложенной папке `fragments/`.
  Их содержимое сохраняется побайтно; старые одиночные архивы остаются читаемыми.
  До 4096 фрагментов в пакете; большой остаток отправляется следующими пакетами.
  Один цикл ограничен четырьмя документами данных, затем обновляется каталог.
- Интервал между документами и закреплениями — минимум 4 секунды: не более
  15 таких операций в минуту для одной группы, ниже ограничения Telegram 20
  сообщений в минуту. Считаются и технические сообщения каталога, и закрепление.
  Для одного бота выдерживается также минимум секунда между такими операциями.
  Расписание сохраняется на диск; ручная отправка его не обходит.
- Размер 19 МБ выбран из-за ограничения облачного `getFile` в 20 МБ: файл на
  50 МБ можно отправить, но нельзя затем получить тем же способом для анализа.
  Собственный Bot API сервер для работы приложения не требуется.
- Очередь хранится в SQLite, лимит полезных данных 128 МиБ. Размер самого файла
  БД может быть больше из-за служебных страниц; освобождённое место переиспользуется.
  При переполнении новые данные не читаются, но отправка старых продолжается.
- При отсутствии сети очередь остаётся на диске. Для включённой автоотправки
  повторные попытки выполняются с увеличивающейся задержкой и учётом `retry_after`.
  Ручная отправка также повторяется до завершения очереди либо до паузы.
  `retry_after` сохраняется для всего бота и переживает изменение настроек,
  повторный клик и перезапуск. Это не гарантия отсутствия 429: другие экземпляры
  с тем же токеном или изменения серверных ограничений не контролируются локально.
  Полученный 429 означает ожидание, а не потерю данных или падение приложения.
- Пауза выключает автосбор. Уже начатый запрос может закончиться; следующие
  загрузки прерываются между запросами. Закрытие через «Выход» ждёт текущий запрос.
- Удаление источника из списка не удаляет уже собранные архивы. В первой версии
  нет кнопки очистки очереди; данные не удаляются неявно.
- Отслеживаются переименование при ротации, уменьшение файла и изменение
  контрольного фрагмента перед текущей позицией. Это **не гарантия отсутствия
  потерь** при произвольном переписывании файла, мгновенной ротации или удалении
  непрочитанных исходников. Настройте достаточное хранение в исходной программе.
- Сетевой обрыв после принятия файла Telegram, но до получения подтверждения
  может создать дубликат сообщения. ID архива остаётся прежним; каталог и CLI
  исключают дубликаты по этому ID. Гарантии exactly-once нет.
- Один сборщик на отдельную группу. Другие закреплённые сообщения могут помешать
  поиску каталога; программа остановится, не изменяя их. Не открепляйте и не
  удаляйте каталоги. При потере закрепления восстановите **последний** каталог.
- Файлы и каталоги в Telegram автоматически не удаляются. Период хранения
  управляется владельцем группы; удаление части цепочки нарушит доступ к старым
  записям через CLI. Не считайте Telegram единственной резервной копией.
- На вкладке «Отправка» есть флажок «Запускать при входе в Windows, сразу в трее».
  Он выключен по умолчанию и применяется сразу, без кнопки «Сохранить».
  Используется запись `LogCourier` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`;
  при выключении удаляется только эта запись. Токен в команду запуска не входит.
  Сам автозапуск не разрешает отправку логов: согласие и автоотправка включаются отдельно.
  После переноса папки программы выключите и снова включите флажок, чтобы обновить путь.
  Если автозапуск отключён в диспетчере задач или политикой Windows, запись Run не
  отменяет это ограничение. В Linux эта настройка недоступна.

## Как получить логи позже

Bot API не предоставляет боту произвольное чтение истории группы. Поэтому после
загрузки архивов LogCourier отправляет документ-каталог с `file_id`, размерами и
SHA-256, связывает его с предыдущим каталогом и закрепляет. Это позволяет
скачать **файлы, зарегистрированные LogCourier**, а не любые вложения группы.

На компьютере с настроенным доступом:

```bash
.venv/bin/python -m logcourier list --limit 20
.venv/bin/python -m logcourier fetch --output ./received --since 2026-09-05 --limit 100
```

В переносимой версии замените `.venv/bin/python -m logcourier` на путь к
`LogCourier` / `LogCourier-cli.exe`. На другом компьютере укажите `--chat-id` и
`--bot-id` и сохраните токен этого же бота в системном хранилище через настройки.
Для автоматизированной среды также поддерживается `LOGCOURIER_BOT_TOKEN`;
не помещайте его значение в историю команд или репозиторий.

`--limit` ограничивает число последних записей **до** фильтра `--since`.
Дата фильтра — UTC. Каталог обходится максимум на 100 страниц в одном запросе.
Архивы проверяются по размеру и SHA-256; другие локальные файлы не перезаписываются.
Архивы не распаковываются автоматически. Старый одиночный формат содержит
`fragment.log` и `metadata.json` с диапазоном байтов, именем источника и признаком
сброса позиции. Новый пакет содержит несколько таких ZIP и общий `manifest.json`.

CLI даёт возможность агенту по вашему запросу скачать и изучить логи, когда
на его компьютере настроен доступ. Само приложение не запускает ИИ-анализ и
не даёт агенту доступ к группе автоматически.

## Приватность

Это **полное содержимое логов, без автоматического обезличивания**. В логах
KeySwitch могут оказаться набранные сообщения. Передаваться будут также имя
устройства, название источника и время сбора; абсолютный путь не добавляется
в метаданные архива, но может присутствовать в самом тексте исходного лога.

Все участники группы могут получить эти файлы. Токен — полномочие управления
ботом, а не ключ «только на отправку». Не распространяйте его другим пользователям;
для них нужна отдельная схема доступа. При утечке перевыпустите токен в BotFather.
ZIP и локальная очередь отдельно не шифруются. Системное хранилище защищает токен,
но не устраняет риски заражённого компьютера или доступа под вашей учётной записью.

Настройки и очередь: Windows `%LOCALAPPDATA%\LogCourier`, Linux
`$XDG_DATA_HOME/logcourier` или `~/.local/share/logcourier`. Для тестового профиля
можно задать `LOGCOURIER_DATA_DIR`. Для переноса устройства сохраняйте настройки
и состояние при остановленном приложении; не запускайте две копии профиля одновременно.

## Разработка и сборка

```bash
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/pytest --cov=logcourier --cov-report=term-missing
.venv/bin/python tools/build.py
```

Команды выполняются из `apps/logcourier`. Сборка выполняется **на целевой ОС**.
Скрипт создаёт переносимую папку и ZIP в
`dist/`. Настройки, токены, очередь и исходные логи в сборку не входят.
Workflow `../../.github/workflows/logcourier.yml` предназначен для тестов и сборки Linux/Windows,
результат проверки Windows нужно сверять с завершившимся запуском CI.
Общий токен в CI не нужен: тесты используют имитацию Telegram и временные файлы.

На Windows после установки зависимостей нужны Inno Setup 6 и команды:

```powershell
python tools/build.py
python tools/verify_frozen.py
python tools/build_installer.py
```

Результат: `dist/LogCourier-Setup-0.1.1-x64.exe` и соседний `.exe.sha256`.
Компилятор ищется в `PATH` и стандартных каталогах Inno Setup 6. Если он отсутствует,
нет полного payload или сборка не удалась, скрипт завершается ошибкой.
В установщик включаются только исполняемые файлы, зависимости, документация и лицензии.
Размер единого файла будет известен после Windows-сборки; соответствие лимиту Telegram
не гарантируется заранее.

Workflow дополнительно запускает `tools/verify_installer.py` на одноразовом Windows runner:
тихую установку в путь с пробелами и кириллицей, версию CLI, запуск и закрытие GUI,
повторную установку, удаление, сохранность тестового профиля и корректную очистку
автозапуска. Этот сценарий намеренно отказывается работать вне CI и при наличии
существующей установки или профиля. Артефакты публикуются только после успешных проверок.

Архитектура: `collector.py` — чтение и ZIP, `store.py` — транзакционная очередь,
`telegram.py` — HTTPS-клиент, `catalog.py` — доставка и связанный каталог,
`service.py` — фоновый цикл, `gui.py` — интерфейс и трей, `__main__.py` — CLI.
Результаты первичной проверки: [docs/VERIFICATION.md](docs/VERIFICATION.md).
