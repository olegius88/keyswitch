# Проверка 0.1.0 — 2026-09-05

## Локальные доработки 2026-09-06 (ещё не опубликованы)

- Исправлена упаковка Windows: оконный `LogCourier.exe`, отдельный консольный
  `LogCourier-cli.exe`. Общие зависимости не дублируются.
- Крестик скрывает окно при доступном трее; при недоступном трее не завершает
  отправку и не оставляет недоступное пользователю скрытое окно.
- Добавлен флажок автозапуска Windows при входе пользователя. Операции с реестром
  проверены на подменённом API, включая ошибку доступа; реальный реестр не менялся.
- Добавлены пакеты до 19 МБ, ограничение частоты и сохраняемая пауза Telegram:
  [проектирование доставки](DELIVERY.md).
- 72 теста прошли, включая 9 проверок подготовки инсталлятора. Общее покрытие
  кода приложения с ветвями около 78%. Проверка сборщика запускается
  из `apps/logcourier`, отдельно от 100%-го порога клавиатурного движка KeySwitch.
  Порог и настройки покрытия KeySwitch не менялись.
- Собранный Linux-бинарный файл прошёл проверку GUI: запуск, закрытие окна,
  повторное открытие, остановка фонового потока и выход. Отсутствие трея в
  offscreen-среде ожидаемо. Windows PE-подсистемы и запуск GUI добавлены в CI.
- Новая Windows-сборка и реальная работа автозапуска после входа ещё не проверены.
  Коммит и push в рамках этой доработки не выполнялись.
- Подготовлен Inno Setup-инсталлятор: установка для текущего пользователя,
  ярлыки, единый `.exe` и SHA-256, удаление без потери профиля и токена.
  Тесты Linux проверили вызов компилятора на имитации, ошибки и неполный payload,
  защиту от устаревшего результата и ограничения установочного сценария.
  Компиляция Inno Setup и цикл установки/обновления/удаления добавлены в Windows CI,
  но **ещё не запускались для этих изменений**. Проверенного Windows-инсталлятора
  пока нет; размер и возможность отправки одним файлом в Telegram пока неизвестны.

## Пройдено локально

- Ubuntu 26.04, Python 3.14.4, PySide6 6.11.2.
- Ruff: проверка ошибок и форматирования.
- Pytest: **44 теста прошли**. Покрытие с учётом ветвей: **76%**; это не полное
  покрытие интерфейса и всех платформенных зависимостей.
- Байтовая сохранность UTF-8, CRLF, пробелов, бинарных данных и длинных строк.
- Добавление данных, базовая позиция без старых записей, rename-ротация,
  copytruncate с повторным ростом, отсутствующий и позже созданный файл.
- Остановка сбора при заполнении очереди без продвижения позиции; доставка
  уже накопленного при заполненной очереди; разделение очередей по получателям.
- Каталог Telegram на имитации API: цепочка, SHA-256, повторы, сбой закрепления,
  восстановление, потерянное и чужое закрепление, остановка после загрузки.
- Транспорт на имитации HTTP: ограничение размера, отказ от перенаправлений,
  повтор после 429, неверный получатель, повреждённый ответ, сокрытие токена.
- CLI: получение каталога, скачивание, проверка контрольной суммы,
  пропуск уже скачанного неизменённого файла.
- GUI: четыре прокручиваемые вкладки, скрытое поле токена, выключенная отправка,
  снятие согласия при смене группы, пауза, завершение фонового потока.
- Настоящий цикл Qt проверен offscreen и через X11/Xvfb; снимки всех вкладок
  сохранены локально в `.local/smoke` и осмотрен экран настройки Telegram.
- PyInstaller: собраны папка приложения, ZIP и SHA-256.
- Собранный бинарный файл: `--version`, `status`, открытие окна через X11/Xvfb
  без ошибок в stderr. Тест использовал отдельный профиль без токена.
- Реальный Telegram: `getMe` подтвердил предоставленного бота;
  секрет сохранён через Linux Secret Service. После команды `/start` обнаружена
  закрытая группа и проверены права администратора на закрепление.
- Сквозной тест `tools/verify_live_telegram.py`: отправлен один синтетический
  ZIP (833 байта), опубликован и закреплён каталог; архив скачан через `getFile`
  и повторно через штатный CLI `fetch`. Размер, SHA-256 и исходное содержимое
  совпали. Очередь теста пуста. Результат: `.local/live-telegram/result.json`.
  Реальные логи не отправлялись, автоотправка и согласие на них выключены.

## Пока не проверено

- Повторная отправка после настоящего сетевого сбоя; восстановление после
  ошибок проверялось на имитации API, без искусственных сбоев живого Telegram.
- Windows: нативные GUI, Credential Locker и исполняемый файл. Workflow для
  тестов и сборки подготовлен, но ещё не запускался на GitHub.
- Системный трей конкретной пользовательской среды: Xvfb не предоставляет
  настоящий рабочий стол с панелью трея. Обработка отсутствующего трея проверена.
- Старые дистрибутивы Linux, автозапуск ОС, длительная многодневная нагрузка,
  произвольные схемы ротации файлов и нескольких одновременно работающих писателей.

После первичной проверки программа перенесена в `apps/logcourier` репозитория
KeySwitch. Её Windows/Linux-сборка запускается отдельным workflow
`.github/workflows/logcourier.yml`; история проверки ниже относится к сборщику,
а не к изменению клавиатурного движка KeySwitch.
