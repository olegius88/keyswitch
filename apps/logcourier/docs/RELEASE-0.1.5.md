# LogCourier 0.1.5

Отдельный выпуск сборщика логов для Windows и Linux с двумя исправлениями. Версия KeySwitch
не меняется.

## Изменения

- Журнал, который logrotate поворачивает копированием (`copytruncate`), читался с самого
  начала: уже отправленные строки уходили в группу ещё раз, а с ними и строки, которые при
  добавлении источника были оставлены неотправленными. Теперь сборщик узнаёт такую копию
  по отпечаткам уже прочитанных частей и продолжает её с того места, до которого дочитал;
  строки, записанные перед самым копированием, тоже уходят, один раз. Журналы, которые
  поворачиваются переименованием (так делает KeySwitch), это не затрагивало.
- Очистка группы в самом начале выбрасывала из очереди все архивы, уже загруженные в группу,
  но ещё не внесённые в каталог, — до того, как становилось ясно, какие сообщения Telegram не
  даст удалить. Теперь такие архивы ждут конца очистки: архивы, чьи сообщения остались в
  группе, попадают в новый каталог, остальные выбрасываются, и итог называет только их число.
  Очистка, начатая версией 0.1.4 и продолженная этой, сообщает свой прежний подсчёт.

## Обновление

Windows: скачайте `LogCourier-Setup-0.1.5-x64.exe`. Перед установкой выберите
«Выход» в трее старого сборщика. Настройки, очередь и системное хранилище токена
сохраняются. Не запускайте одновременно две копии с одним профилем.

Установщик не включает отправку и автозапуск без вашего выбора. Личные логи,
токены и приватные инструкции в дистрибутив не входят. Linux ZIP собирается
на Ubuntu 26.04; более старые дистрибутивы не проверены.

## Проверки и ограничения

Перед публикацией требуются успешные нативные сборки Windows и Linux,
проверка упакованного GUI, а на Windows — установка, обновление и удаление.
Контрольные суммы SHA-256 поставляются рядом с файлами.

Оба исправления проверены тестами, и оба теста падают на коде 0.1.4. Ротация копированием
проверена на файлах во временном каталоге: копия делается так же, как `copytruncate`, а
живой файл опустошается на месте. Очистка проверена на имитации Telegram, которая отвечает
на удаление так же, как живой Bot API (сверено при подготовке 0.1.4). С настоящим logrotate
и на живой группе эти два сценария в рамках выпуска не запускались.
