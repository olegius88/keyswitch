# LogCourier

Личный сборщик логов для Windows и Linux. Он читает выбранные файлы журналов,
складывает новые фрагменты в локальную очередь и отправляет их ZIP-архивами в
закрытую группу Telegram. Это отдельная программа репозитория KeySwitch
(`crates/logcourier`): в пакеты и установщики KeySwitch она не входит и
обработку клавиатуры не меняет. Отправка по умолчанию выключена: её включает
разрешение на вкладке «Отправка».

В Windows программа живёт в трее: крестик прячет окно, сбор продолжается.
Левый щелчок по значку открывает окно, правый — меню «Открыть настройки»,
«Отправить сейчас», «Приостановить автосбор», «Выход». Вторая копия не
запускается и напоминает о значке в трее.

В Linux трея нет. Крестик тоже только прячет окно, сбор продолжается; повторный
запуск программы показывает окно уже работающей копии, а кнопка «Выход» на
вкладке «Состояние» завершает её.

## Сборка и запуск

Нужен Rust ([rustup](https://rustup.rs)). Команды выполняются из корня
репозитория.

### Linux

```bash
sudo apt install build-essential libgtk-4-dev curl libsecret-tools
cargo run --release -p logcourier
```

`build-essential` даёт компилятор C: им Rust компонует программу, и им же
собирается SQLite, которая входит в программу. Окно требует GTK 4.10 или новее. Запросы к Telegram
программа делает через системный `curl`, а токен хранит в Secret Service через
`secret-tool` из пакета `libsecret-tools`.

Собранные файлы — `target/release/logcourier` и `target/release/logcourier-cli`.
В Linux они работают одинаково.

### Windows

Нужен Rust с целью MSVC: установщик rustup предложит поставить Visual Studio,
которая даёт компоновщик и системные библиотеки.

```powershell
cargo run --release -p logcourier
```

`target\release\logcourier.exe` — оконная программа без консоли,
`target\release\logcourier-cli.exe` — та же программа для команд в терминале.
`curl` есть в каждой установке Windows 10 и 11
([curl.se](https://curl.se/windows/microsoft.html)).

### Установщик для Windows

Нужен Inno Setup 6 в стандартной папке `%ProgramFiles(x86)%\Inno Setup 6`.

```powershell
.\packaging\build-logcourier.ps1
```

Скрипт собирает программу для `x86_64-pc-windows-msvc` со статически связанной
библиотекой C (`+crt-static`) и кладёт в `dist\LogCourier` переносимую копию: `LogCourier.exe`,
`LogCourier-cli.exe` и `LICENSE`. Рядом появляется установщик
`dist\LogCourier-Setup-<версия>-x64.exe`; версия берётся из
`crates/logcourier/Cargo.toml`, папку установщика меняет `-OutputDirectory`.

Установщик ставит программу для текущего пользователя в
`%LOCALAPPDATA%\Programs\LogCourier` без прав администратора, создаёт ярлык в
меню «Пуск» и, по желанию, на рабочем столе, и после установки предлагает
запустить LogCourier. Автозапуск и отправку он не включает. Удаление убирает
программу и её запись автозапуска, если та указывает на эту копию; настройки,
очередь и токен остаются. При установке поверх прежней версии удаляются папка
`_internal` и `README.md`, которые та держала рядом с программой.

Настройки, очередь и токен лежат там же и в том же виде, что у выпусков 0.1.x,
поэтому прежний профиль продолжает работать.

## Подключение Telegram

1. Создайте отдельного бота через `@BotFather`.
2. Создайте закрытую группу без публичного @имени и добавьте бота
   администратором с правом «Закрепление сообщений». Право «Удаление
   сообщений» нужно только для очистки группы (раздел «Как начать заново»).
3. На вкладке «Telegram» вставьте токен в поле «Токен». Флажок «Сохранить токен
   в системном хранилище секретов» включён по умолчанию.
4. Отправьте в группе `/start@имя_вашего_бота` и нажмите «Найти группы».
   Поиск смотрит последние обновления бота, а не историю группы. Если группа не
   нашлась, введите её отрицательный Chat ID в поле «ID группы (Chat ID)». Если у
   бота настроен webhook, поиск не работает и webhook не меняет: введите ID вручную.
5. Нажмите «Проверить подключение». Проверка ничего не отправляет: она
   сверяет бота с токеном, тип группы и права бота.
6. На вкладке «Файлы» нажмите «Добавить файл» и выберите лог, например журнал
   KeySwitch `keyswitch.log`. Его ротации LogCourier читает сам, по умолчанию
   пять (`keyswitch.log.1` … `.5`); отдельными источниками их не добавляйте,
   иначе сбор задвоится. Флажок «Включить уже существующие записи и ротации»
   отправит и накопленное; без него сбор начнётся с конца файлов при первом
   запуске сбора, а не в момент выбора файла.
7. На вкладке «Отправка» поставьте флажок «Разрешаю отправлять содержимое
   выбранных логов в эту группу Telegram» и нажмите «Отправить сейчас». Когда в
   очереди есть данные, в группе появляются архив и закреплённый каталог.
8. При необходимости включите «Автоматически собирать и отправлять логи»,
   выберите интервал и нажмите «Сохранить».

Новый токен или другая группа снимают разрешение на отправку: нового получателя
нужно подтвердить заново. Архивы, собранные для прежних бота и группы, остаются
в очереди и сюда не уходят; вкладка «Состояние» показывает их число.

При переносе на другой компьютер остановите сборщик на прежнем и нажмите на новом
«Подключить существующий каталог (перенос с другого компьютера)». Программа
продолжит каталог, уже закреплённый в группе, если локальная очередь в эту группу
пуста. Разрешение на отправку и автоотправку после переноса нужно включить снова.
Два сборщика в одну группу одновременно не запускайте.

В Windows на вкладке «Отправка» есть флажок «Запускать при входе в Windows, сразу
в трее». Он выключен по умолчанию и применяется сразу, без «Сохранить»: программа
пишет в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` значение
`LogCourier` с командой `"<путь>\LogCourier.exe" gui --minimized`, а при
выключении удаляет только его. Токена в этой команде нет, и сам автозапуск
отправку не разрешает. После переноса папки программы выключите и снова включите
флажок, чтобы путь обновился. В Linux такой настройки нет.

## Настройки и данные

Каталог данных: в Windows `%LOCALAPPDATA%\LogCourier`, в Linux
`$XDG_DATA_HOME/logcourier`, а без этой переменной `~/.local/share/logcourier`.
Переменная `LOGCOURIER_DATA_DIR` задаёт другой каталог, например для отдельного
тестового профиля. В каталоге лежат `config.json` (настройки) и `state.sqlite`
(очередь, позиции чтения, расписание отправки). Сохраняйте и переносите их при
остановленной программе.

Поля `config.json` (окно пишет их само):

| Поле | Что значит | Пределы |
| --- | --- | --- |
| `device_id` | идентификатор этого сборщика | 32 шестнадцатеричных знака |
| `device_name` | имя устройства в подписях архивов | 1–80 знаков, по умолчанию «Мой компьютер» |
| `chat_id` | ID группы | отрицательное число или пусто |
| `bot_id` | ID бота, первая часть токена | число или пусто |
| `interval_minutes` | интервал автоотправки | 1–1440 минут, по умолчанию 15 |
| `auto_send` | автоматический сбор и отправка | по умолчанию `false` |
| `consent` | разрешение отправлять содержимое логов | по умолчанию `false` |
| `sources` | источники, не больше 50 | см. ниже |

У источника: `path` — абсолютный путь к файлу, `label` — название (1–80 знаков),
`rotations` — сколько ротаций `.1` … `.N` читать (0–20, по умолчанию 5),
`include_existing` — отправлять ли накопленное, `id` — 32 шестнадцатеричных
знака. Один файл дважды не добавляется. `config.json` больше 1 МиБ, с неизвестным
полем, неверным типом или значением вне пределов программа не читает и не меняет;
окно тогда не открывается, отправка не начинается.

Токена в `config.json` нет. Он хранится в системном хранилище под именем
`LogCourier.Telegram`: в Windows — в учётных данных Windows, в Linux — в Secret
Service с атрибутами `service LogCourier.Telegram` и `username <ID бота>`. Если
хранилище недоступно, снимите флажок сохранения: токен будет действовать до
выхода из программы. Снятый флажок уже сохранённый токен не удаляет; удалить его
можно средствами системы: `cmdkey /delete:LogCourier.Telegram` в Windows,
`secret-tool clear service LogCourier.Telegram username <ID бота>` в Linux.

Переменная `LOGCOURIER_BOT_TOKEN` подставляет токен вместо хранилища и в окне, и в
командах; не оставляйте её значение в истории команд или в репозитории.

## Команды

В Windows команды выполняет `LogCourier-cli.exe`, в Linux — `logcourier` или
`logcourier-cli`.

| Команда | Что делает |
| --- | --- |
| без аргументов или `gui` | открывает окно |
| `gui --minimized` | запускает без окна, если бот уже настроен; так стартует автозапуск Windows |
| `--version` | печатает версию |
| `status` | печатает JSON: версию, `chat_id`, `bot_id`, `auto_send` и число источников |
| `list` | печатает JSON со списком архивов из закреплённого каталога |
| `fetch --output <папка>` | скачивает эти архивы |
| `self-test [--output <файл>]` | строит окно на временном профиле, не показывая его; с `--output` пишет JSON с версией и числом вкладок. В Linux нужен дисплей |

Параметры `list` и `fetch`:

- `--chat-id <ID>` и `--bot-id <ID>` — группа и бот, если они не те, что в
  настройках, например на другом компьютере. Токен этого бота нужен в системном
  хранилище или в `LOGCOURIER_BOT_TOKEN`; в аргументах токен не принимается.
- `--limit <N>` — сколько последних архивов взять, от 1 до 10 000, по умолчанию 20.
  Лимит считается после отбора по версии и до `--since`; маркеры версий его не
  расходуют. Каталог просматривается не дальше 100 страниц за запрос.
- По умолчанию берутся только архивы текущей версии KeySwitch каждого источника;
  если каталог ещё не знает версии, команда останавливается и объясняет почему, а
  старые архивы вместо новых не подставляет. `--keyswitch-version X.Y.Z` выбирает
  одну версию, `--all-versions` — всю историю, в том числе логи других программ и
  архивы без версии. Эти два параметра вместе не задаются.
- `--since ГГГГ-ММ-ДД` (только `fetch`) — архивы, созданные в этот день и позже,
  по UTC.

```bash
logcourier list --limit 20
logcourier fetch --output ./received --since 2026-11-01 --limit 100
logcourier fetch --keyswitch-version 0.66.2 --output ./received
logcourier fetch --all-versions --output ./history --limit 100
```

`fetch` сверяет размер и SHA-256 каждого архива, не перезаписывает чужие файлы и
не распаковывает архивы. Для текущей или указанной версии он создаёт подпапку
`keyswitch-current-<идентификатор>` или `keyswitch-<версия>-<идентификатор>` и,
когда скачаны все архивы, кладёт в неё `selection.json` с точным списком файлов,
версий, источников и SHA-256. Для анализа берите эту завершённую подборку, а не
всю папку `--output`. С `--all-versions` архивы ложатся прямо в `--output`.

Код выхода: 0 — готово, 1 — ошибка, 2 — неверные аргументы.

## Что уходит в группу

- Фрагмент — ZIP с `fragment.log` (исходные байты) и `metadata.json`: диапазон
  байтов, название источника, имя устройства, время, версия KeySwitch, признак
  того, что позиция чтения сброшена.
- Перед отправкой фрагменты объединяются в пакет до 19 000 000 байт и до 4096
  фрагментов: ZIP с `manifest.json` и исходными ZIP в папке `fragments/`.
  Фрагменты с версией KeySwitch попадают в пакет только вместе с фрагментами того
  же источника и той же версии. Искусственного дополнения до предела нет: при
  наступлении интервала уходит то, что накопилось.
- Маркер версии `lc-version-<идентификатор>.json` с подписью «МАРКЕР ВЕРСИИ».
- Каталог `lc-index-<идентификатор>.json` со списком отправленных архивов, их
  `file_id`, размерами и SHA-256. Каждый каталог ссылается на предыдущий и
  закрепляется в группе, а SHA-256 каталога стоит в подписи сообщения.

Каталог нужен потому, что бот не может читать историю группы
([messages.getHistory](https://core.telegram.org/method/messages.getHistory)
доступен только пользователям): `list` и `fetch` находят только архивы, записанные
в каталог. Предел 19 МБ выбран потому, что бот может скачать через `getFile` не
больше 20 МБ, хотя отправить может до 50 МБ.

## Поведение и ограничения

- Читаются только выбранные обычные файлы и их числовые ротации. Символьные
  ссылки, устройства, каналы и `.gz` не читаются. Исходные файлы не меняются.
- Пока отправка включена (автоматически или кнопкой), сбор идёт раз в 5 секунд,
  до 16 фрагментов за проход. Фрагмент — до 2 МиБ до сжатия, по возможности по
  границе строки; очень длинная строка или многобайтовый символ могут
  разрезаться, поэтому байты нужно склеивать до декодирования.
- Ротация переименованием, ротация копированием (`copytruncate`), уменьшение файла
  и изменение байтов перед позицией чтения отслеживаются. Это не гарантия от
  потерь, если исходная программа удаляет ещё не прочитанные записи: держите в
  ней достаточный срок хранения.
- Очередь — SQLite, до 128 МиБ полезных данных. Когда она полна, новые данные не
  читаются, а отправка старых продолжается. Записи об архивах, которые уже вошли в
  каталог, удаляются из очереди через 30 дней.
- За один цикл уходит не больше четырёх документов очереди, затем обновляется
  каталог. Между документами, закреплениями и сообщениями в одной группе — не
  меньше 4 секунд, то есть не больше 15 в минуту, ниже предела Telegram в 20
  сообщений в минуту для группы. Между запросами одного бота, которые что-то
  меняют, — не меньше секунды; удаление сообщений при очистке группы выдерживает
  только эту секунду.
- Без сети очередь остаётся на диске. После ошибки повтор идёт через 15 секунд,
  затем вдвое дольше, но не реже раза в 15 минут, и не раньше, чем просит
  Telegram (`retry_after`). Пауза, которую назначил Telegram, хранится на диске для
  всего бота и переживает перезапуск; «Отправить сейчас» её не обходит.
- «Отправить сейчас» отправляет очередь до конца; «Пауза» выключает
  автоматическую отправку, а уже начатый запрос может завершиться.
- Обрыв сети после того, как Telegram принял файл, но до ответа, может дать
  повторное сообщение с тем же ID архива. Каталог и `list`/`fetch` повторы по ID
  отбрасывают.
- Одна группа — один сборщик. Если в группе закреплено чужое сообщение, отправка
  останавливается и ничего не меняет. Не открепляйте и не удаляйте каталоги.
- Сами файлы в Telegram не удаляются, только кнопкой очистки группы.

## Версии KeySwitch

Версию программа берёт из заголовков записей самого KeySwitch, например
`2026-11-07 10:15:00,123 0.66.2 INFO keyswitch.logsetup: …`: это версия процесса,
который записал лог. Номер версии внутри текста сообщения не используется.

- Версия определяется по последней записи в последнем 1 МиБ живого файла, а если
  он пуст или его нет — ближайшей ротации. Если там нет узнаваемого заголовка,
  версия не угадывается.
- При первой найденной версии и при каждой её смене, в том числе откате, в
  очередь встаёт маркер версии. Он уходит вместе с очередью и не закрепляется.
  Перезапуск с той же версией маркера не создаёт.
- Фрагмент никогда не смешивает версии, даже если программа обновилась посреди
  файла, и пакет тоже: фрагменты с версией объединяются только в пределах одного
  источника и одной версии.
- Старая очередь может прийти после маркера, поэтому границу для анализа задают
  метаданные версии, а не порядок сообщений в группе.

## Как начать заново

Кнопка «Очистить группу и начать заново…» на вкладке «Отправка» спрашивает, что
сделать: удалить сообщения и начать заново, начать заново без удаления или ничего
не менять. Ход и итог видны на вкладке «Состояние». Сборщик:

1. проверяет, что бот — администратор с правом закреплять сообщения (и удалять,
   если сообщения удаляются), группа — супергруппа, если сообщения удаляются, и
   что закреплён каталог этого же сборщика или он уже отправлял сюда архивы.
   Иначе группа не меняется;
2. при удалении отправляет короткое сообщение, чтобы узнать номер последнего
   сообщения группы;
3. снимает все закрепления и со следующей отправки начинает новую цепочку
   каталогов. Прежние архивы в неё не входят, и `list` с `fetch` их больше не
   находят;
4. при удалении удаляет сообщения пачками по 100, от новых к старым.

Telegram разрешает боту удалять только сообщения младше 48 часов и отвергает
пачку целиком, если в ней есть хоть одно более старое. Сборщик делением пополам
находит, с какого номера сообщения ещё удаляются, а более старые не запрашивает;
итог называет, до какого номера сообщения остались, — их можно удалить вручную.
Служебное сообщение о создании группы не удаляется.

Неотправленная очередь сохраняется и уходит в новый каталог. Архивы, которые уже
загружены, но ещё не внесены в каталог, тоже попадают в новый каталог, если
Telegram оставил их сообщения в группе; удалённые вместе с группой итог считает.
Прерванная очистка продолжается с того же места, когда отправка снова включена,
или по той же кнопке.

Если отправка остановилась из-за того, что закрепление каталога потеряно или
изменено (например, группу очистили вручную вместе с каталогом), эта же кнопка
начинает каталог заново.

## Приватность

LogCourier отправляет полное содержимое логов, без обезличивания. В логах
KeySwitch может оказаться набранный текст. Кроме того, передаются имя устройства,
название источника и время сбора; путь к файлу в метаданные не входит, но может
встречаться в самом тексте лога.

Файлы видны всем участникам группы. С токеном можно вызывать любой метод Bot API
от имени бота, а не только отправлять файлы: не передавайте его другим людям, а
при утечке выпустите новый командой `/token` в BotFather. ZIP-архивы и локальная
очередь отдельно не шифруются. Журнал состояния не содержит токенов и фрагментов
логов, а из сообщений об ошибках токен вырезается.

## Разработка

```bash
cargo clippy -p logcourier --all-targets
cargo test -p logcourier
```

Тесты не ходят в Telegram: доставку проверяют на подставном клиенте, а команды —
со своим `curl` первым в `PATH`, поэтому токен им не нужен. CI выполняет эти
команды на Ubuntu и Windows и собирает `cargo build --release -p logcourier`.

Устройство: `collector.rs` — чтение файлов и ZIP фрагментов, `store.rs` — очередь
в SQLite, `versions.rs` — версии KeySwitch и маркеры, `batching.rs` — пакеты,
`telegram.rs` — Bot API через `curl`, `rate_limit.rs` — темп запросов,
`catalog.rs` — доставка и цепочка каталогов, `reset.rs` — очистка группы,
`service.rs` — фоновый цикл, `config.rs` и `secrets.rs` — настройки и токен,
`gui_gtk.rs` и `gui_win.rs` — окна Linux и Windows, `cli.rs` — команды.
